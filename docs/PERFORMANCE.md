# 速さの計測と改善の記録

加工の速さと画面の描き直しについて、測った値と、試したこと（採ったもの、採らなかったもの）を記録する。仕組みそのものは [INTERNALS.md](INTERNALS.md) と [ALGORITHM.md](ALGORITHM.md) を参照。

## 加工の段階ごとの速さ
ベンチ `bench_stages`（dsp。3 分、48kHz、ステレオ、+5 半音）で測る。開発 PC では ±10% ほどぶれる（2026-10-02）。

| 段階 | 改善前 | 改善後 | 行ったこと |
| --- | --- | --- | --- |
| FFT 2048（67,500 回） | 1.25 秒 | 0.77 秒 | 最初の 2 段（2 点と 4 点）を、4 点ずつまとめて直接計算する |
| Phase Vocoder | 3.2 秒（うち FFT 約 0.7 秒） | 2.8〜3.0 秒 | ピークの回し量の計算で、atan2 を 3 回から 1 回にする。正弦波のテストではピークが少ないので、実際の曲ではもっと効く見込み |
| フォルマント補正 | 3.5 秒（うち FFT が 53%） | 2.6〜2.9 秒 | FFT の改善と、ln と exp を速い近似（誤差 1e-5〜1e-4、結果のずれは振幅の 0.002%）にする。設定の「開発者向け」→「フォルマント補正の高速計算」で標準の関数に戻せる |
| リサンプル | 0.9〜1.05 秒 | 0.58 秒 | 内積を 8 本の和に分け、SIMD で計算しやすくする |
| SOLA | 0.4 秒 | — | — |

採らなかったもの:
- FFT の radix-4（2 段ずつまとめる）: ネイティブで 2 倍ほど遅くなった
- フォルマント補正の対数振幅を半分だけ計算する（左右対称を使う）: 計測のぶれに埋もれて効果が見えなかった

次に削るなら、フォルマント補正の窓かけ（1ch あたり 0.16 秒）と FFT が残る。FFT を実数専用（半分の長さの複素 FFT）にする余地はあるが、Phase Vocoder とフォルマント補正はすでに 2 フレームを 1 回の複素 FFT に詰めているので、効果は小さい見込み。

## ループ試聴の位置合わせ
ワークレットで、つなぐ位置を ±10ms の範囲で正規化相互相関により探す（既定で ON。設定の「開発者向け」で切れる）。合成音では、周期のきれいさが 0.75〜0.97 から 1.00 になった。128 サンプルごとの処理は 1ms 以下（Node で計測。2026-10-02）。

## 操作中の描き直し
スライダーや範囲のドラッグが重かったので、次の順に直した（2026-10-02〜03）。今の仕組みは [INTERNALS.md](INTERNALS.md) の再生の節を参照。

1. 波形（Waveform）を memo にし、App から渡す関数を `useStableFn` で変わらないようにした
2. 選択範囲を、再生位置の線と同じ重ねた Canvas に描くようにした（ドラッグ中に波形、スペクトログラム、ピッチの線を描き直さない）
3. ドラッグ中の範囲は波形の中だけで持ち、離したときに App へ渡すようにした（ステータスバーの数値は離したときに変わる）
4. トラックの欄（TrackPanel）も memo にした。カーソルの形は状態に持たず、Canvas の style を直接書き換える（マウスを動かすだけで波形を描き直していた）
5. 子の部品を `stableMemo` で包んだ

本番のビルドでは、スライダーのドラッグ中も 58FPS で、App の描き直しは重さとして出ていないので、App の作り替えはしない。描画の回数はデバッグ表示（Ctrl+Shift+D）で確かめられる。
