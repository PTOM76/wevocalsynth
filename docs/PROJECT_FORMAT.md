# プロジェクトファイル（.wvsp）の形式
WeVocalSynth の作業（トラックの音声・加工のパラメータ・テンポ・マーカーなど）を保存するファイルの形式。読み書きは [src/project/projectFile.ts](../src/project/projectFile.ts)（`saveProject` / `loadProject`）。

元に戻す履歴は保存しない（音声を丸ごと持つため、ファイルが大きくなりすぎる）。

## 全体の並び
圧縮しない。数値はすべてリトルエンディアン。

| 位置 | 大きさ | 内容 |
| --- | --- | --- |
| 0 | 4 バイト | 印 `WVSP`（ASCII） |
| 4 | 4 バイト | ヘッダ JSON の長さ（バイト、u32） |
| 8 | ヘッダの長さ | ヘッダ JSON（UTF-8） |
| 8 + ヘッダの長さ | 残り | 音声データ |

## ヘッダ JSON

| キー | 型 | 内容 |
| --- | --- | --- |
| `version` | 数値 | 形式の版（今は 3） |
| `fileName` | 文字列 | プロジェクト名（拡張子なし。古いファイルは拡張子付きのことがある） |
| `named` | 真偽（省略可） | プロジェクト名を利用者が変えたか（変えていなければ、書き出しの名前に `_wevocal` を付ける） |
| `params` | オブジェクト | 加工の欄のパラメータ（`EditParams`。ピッチ・長さ・フォルマント・処理モードなど） |
| `tempo` | オブジェクト（省略可） | `{ bpm, beatsPerBar, beatOffset }`。1拍目の位置は秒 |
| `markers` | 配列（省略可） | `{ id, time, name }`。位置は秒 |
| `tracks` | 配列 | トラックごとの名前と、音声以外の状態（下の表）。版 2 から |
| `active` | 数値（省略可） | 編集していたトラックの位置（0 から） |
| `clips` | 配列 | 音声の並び（下の表）。トラックごとに原音・加工後の順で 2 つずつ |

`tracks` の各要素（音声以外の状態。古いファイルには無いものがあり、無ければ既定値）:

| キー | 内容 |
| --- | --- |
| `name` | トラック名 |
| `volume`・`pan`・`invert` | フェーダー（音量 dB・パン -1〜1・位相反転） |
| `mute`・`solo` | 鳴らし方 |
| `overlay` | 大きな波形の後ろに重ねて表示するか |

正確な一覧は `StoredTrackSettings`（[src/audio/tracks.ts](../src/audio/tracks.ts)）。

`clips` の各要素:

| キー | 内容 |
| --- | --- |
| `sampleRate` | サンプルレート（Hz） |
| `channels` | チャンネル数 |
| `length` | 1 チャンネルのサンプル数 |
| `same` | 真なら、中身を書かず、直前のクリップ（そのトラックの原音）と同じ。加工していないトラックの加工後に使う。版 3 から |

## 音声データ
`clips` の順に、各クリップのチャンネルを順に並べる。1 サンプルは f32（リトルエンディアン、-1〜1）。1 チャンネルの大きさは `length × 4` バイト。`same` のクリップは何も書かない。

例: 2 トラック（1 本目は加工済み、2 本目は加工していない）、どれもステレオ

```text
トラック1の原音 L, トラック1の原音 R, トラック1の加工後 L, トラック1の加工後 R,
トラック2の原音 L, トラック2の原音 R                      （トラック2の加工後は same）
```

## 版ごとの違い

| 版 | 内容 |
| --- | --- |
| 1 | トラックが 1 本だけ。`tracks` は無く、クリップは原音・加工後の 2 つ。読むときは 1 トラックとして扱う |
| 2 | 複数のトラック。`tracks` にトラックごとの名前と状態を持つ |
| 3 | 加工後が原音と同じトラックは、加工後を `same` にして書かない（大きさが半分になる）。2026-10-03 から |

さらに古いファイルは全体を gzip で圧縮していた（先頭が `1f 8b`）。読むときは展開してから同じように読む。音声はほとんど縮まず（約 1 割）、保存に数秒かかったので、今は圧縮しない。

新しい版のファイルは、古い版のアプリでは開けない（`project.unsupported` になる）。

## 読み書きの工夫
- 書くとき: f32 の配列を、リトルエンディアンの端末ではそのままバイト列として使う（1 サンプルずつ変換すると、3 分の音声で数秒かかった）
- 読むとき: チャンネルごとにファイルの必要な部分だけを読む（`Blob.slice`）。全体を読んでから切り出すと、一時的にファイルの 2 倍のメモリを使った。3 分・ステレオで、版 2（138MB）が 0.7 秒、版 3（69MB）が 0.4 秒（2026-10-03、開発 PC）

自動保存はこの形式を使わず、IndexedDB にトラックごとの `Float32Array` をそのまま置く（[INTERNALS.md](INTERNALS.md) の「保存」）。
