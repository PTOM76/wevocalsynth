# 決定事項
実装していて問題を踏み、その結果として決まったもの。知らずに触ると同じ問題を踏むので、新しいコードでも同じようにする。

設計全体の方針は [ARCHITECTURE.md](ARCHITECTURE.md)、書き方の決まりは [CODING.md](CODING.md) を参照。

## 音声処理

### 伸長の最後のフレームは、入力の最後のフレームに合わせる
最初は出力位置を伸縮率で割って入力位置を決めていた。これだと末尾でフレームが入力の終端をはみ出して無音を重ね合わせ、伸ばした音の最後だけギザギザになった。
はみ出さないよう位置を止めると、今度は最後の断片を何度も繰り返してうなりになった。

そのため `TimeMap::frame_pos` で「最後の出力フレーム＝最後の入力フレーム」になるよう対応づけている。すべての伸縮方式がこれを通る。テストは `stretch_tail_is_steady`。

### WSOLA の類似度はフレームの重なる部分だけで計算する
フレーム全体で比べると、末尾では比較する範囲が入力の外にはみ出す。重なる前半だけで比べれば常に入力の内側に収まり、計算量も半分になる。

### ピッチ変更は「伸縮してからリサンプル」で行う
長さはピッチ比に影響されず、ピッチ変更と時間伸縮を1回で指定できる。処理の順番で結果が変わる心配もない。

### 新しい処理方式を入れても、前の方式は残して選べるようにする
方式ごとに得意な音が違い、新しい方式がどの素材でも良いとは限らないため。既定はボーカル＝SOLAv3、楽器＝Phase Vocoder で、処理モードの「…」からほかの方式も選べる。ボーカルの既定は PSOLA → SOLA（2026-10-02。にじみが少なく、聞き比べて一番自然だった）→ SOLAv2 → SOLAv3（2026-10-03）と変えてきた。改良版（PSOLAv2、WSOLAv2、SOLAv2 など）は、従来版を置き換えずに別の方式として追加した。改良版がある従来の方式は、選択肢が多すぎるので既定では隠し、設定で表示できるようにした (2026-10-03)。画面では方式名の代わりに愛称（Solis など）を表示する（[アルゴリズム](ALGORITHM.md)）。

### 区切り位置は2乗誤差で探し、ゼロクロス点では区切らない
ゼロクロス点で区切る方式を試作して比べた。ボーカルもどきを4倍に伸ばしたときの周期のきれいさは、2乗誤差（SOLA）の 0.997 に対して 0.986〜0.995 で、低い声ほど悪かった。倍音が多いと位相が揃わないため。計算が軽い利点も、今の SOLA が十分速いので活きない (2026-09-30)。

### Phase Vocoder で2本をまとめて逆 FFT するときは、直流とナイキストのビンを実数にする
位相を回すと直流とナイキストのビンに虚部が付く。1本ずつ逆変換すれば虚部は出力の虚部に現れて捨てられるが、2本を実部・虚部に詰めてまとめると相方に漏れた（直流の大きい音で大きくずれた）。
また、まとめるのは同じチャンネルの隣り合うフレームにする。違うチャンネル同士だと、大きな雑音側の計算誤差が相方の静かな帯域に漏れ、偽のピークができて結果が揺れた。

### フォルマント補正はリサンプルの前に行う
リサンプルの後だとピッチが上がって倍音の間隔が広がり、包絡をうまく推定できない。前なら元の声の高さのまま推定できる。

### ボーカル／楽器の自動判定は目安として扱う
「鳴っているフレームのうちピッチが取れた割合」で判定している。正弦波の和音は1つの長い周期を持つため、「ボーカル」と誤判定される（合成音で確認）。
初期値を決めるだけにし、画面の切り替えを優先する。実際の素材での精度はまだ確かめていない (2026-09-27 時点)。

### リアルタイムのループ試聴は、適用とは別の簡易な方式を使う
適用時の方式（PSOLA・WSOLA・Phase Vocoder など）は音声をまとめて処理する前提で、再生しながら少しずつ処理する形にするのは重い。
ループ試聴は AudioWorklet のグラニュラー方式にし、「適用」と通常の「試聴」は高品質な処理のままにした。音がザラつくのはこの割り切りのため。

### ツールバーのループは通常の再生の繰り返しにし、加工の欄のループと分ける
もとはツールバーのループも加工の欄と同じリアルタイム試聴だったが、別の AudioContext で選択中のトラックのみを鳴らすため、メーター・フェーダー・ほかのトラックが反映されず、再生位置の線も動かなかった。範囲を繰り返し聴きたいだけのときは通常の再生（`usePlayer`）を繰り返す形にし、スライダーを動かしながら聴くリアルタイム試聴は加工の欄に残した (2026-10-02)。

## 実行と読み込み

### スペクトログラムと F0 は、表示を ON にしたときだけ計算する
ファイルを開いたときに表示の ON/OFF とパラメータを前のファイルから引き継いでいた。そのため開いた直後にスペクトログラム・F0・プレビューの処理が Worker に積まれ、読み込みが遅く感じられた。
今はファイルを開くと表示を OFF、パラメータを初期値に戻す。処理方式とフォルマント保持の ON/OFF だけは、好みの設定として残す。

### 再生位置を画面全体の状態にしない
再生位置を React の状態として 60回/秒 更新していたころは、再生中ずっと画面全体（MUI の部品が多い）が描き直され、1回に 50ms 以上かかって FPS が 20 まで落ちた。
再生中は状態を更新せず、再生位置の線・時間の表示・自動スクロールが `livePosition()` を自分で読む。これで FPS 60、長いタスク 0 になった。

### DSP の Worker は加工用と解析用の 2 つにする
Worker を増やすと WASM のメモリをその数だけ持つことになり、長い音声では足りなくなる。一方で 1 つだけだと、ファイルを開いた直後の解析の後ろで「適用」が待たされ、止まったように見えた。そのため加工用と解析用の 2 つにし、それぞれの中では届いた順に処理する。解析の結果は「どのクリップのものか」を確かめてから使う（古い結果を捨てる）。

### プレビューは、同じ設定のときだけ使い回す
「適用」で加工済みプレビューを差し込むときは、クリップ・範囲・パラメータがすべて同じかを確かめる。1つでも違うものを差し込むと、画面の設定と違う音になる。

### 追加機能のファイルは、ページを開く操作では保存先から返さない
`addons/` を保存先（Cache Storage）から返す設定が、ページを開く操作まで拾っていた。そのうえ、ページを開く操作はアプリ本体の `index.html` で返す設定（オフライン起動用）とも重なり、`addons/` のページを開くとアプリの画面になった。
そのため [vite.config.ts](../vite.config.ts) で、`addons/` はページを開く操作の対象から外し（`navigateFallbackDenylist`）、保存先から返すのはページを開く操作以外に限っている (2026-10-01)。

### 追加機能の進捗表示に Content-Length を使わない
GitHub Pages は `application/octet-stream` も gzip で配信し、`Content-Length` は圧縮後の大きさになる（乱数の 40MB で元より約 13KB 大きかった）。進捗はマニフェストに書いた元の大きさで計算する (2026-10-01)。

### Spleeter の fp16 版は WebGPU で動かさない
ONNX Runtime Web 1.30 の WebGPU で fp16 版を動かすと、エラーにならずに出力がすべて 0 になった。入力は正しく渡っていた。int8 版・fp32 版は WebGPU でも正しく抽出できたので、fp16 版のときだけ WASM で動かす (2026-10-01)。

### 再生のたびに作った部品は、止めたらすべて切り離し、AudioContext も止める
最初は止めるときに音源だけを切り離していて、その後ろの部品（音量・パン・フェーダー・ミュート・メーター）が全体の出口につながったまま残り、無音を処理し続けていた。再生・停止を繰り返すほど増えるので、開いたまま使い続けると重くなった。
今は再生のたびに作った部品を覚えておき、止め方（停止・一時停止・最後まで再生・クリップの切り替え）によらず切り離す。止めている間は AudioContext を一時停止する（ループ試聴も同じ） (2026-10-01)。

### ミュート・ソロで鳴らさないトラックも再生しておく
再生を始めるときに鳴らすトラックだけを選ぶと、再生中にミュート・ソロを押しても次に再生し直すまで変わらなかった。全トラックを再生し、トラックごとの音量（1 / 0）だけを切り替える。AudioBufferSourceNode は軽いので、数本なら負担にならない (2026-10-01)。

### パンは StereoPannerNode と同じ式で、適用・書き出しする
試聴は StereoPannerNode、適用（`panRange`）と書き出し（`applyFader`）は JS で計算する。式をそろえないと、聴いた音と結果がずれる。モノラルは左右同じ音のステレオにしてから掛ける（StereoPannerNode のモノラル用の式だと、パン 0 でも音量が下がるため） (2026-10-01)。

### 追加機能は、使う直前に版も確かめる
導入済みかだけを見ていたら、古い実行環境のまま新しい関数（`separateBoth`）を呼んで失敗した。配信中のマニフェストと版が違えば、更新の確認ダイアログを表示する。オフラインなら今ある版で使う (2026-10-01)。

### スペクトログラムは WeVocalAnalyzer に移し、追加機能として使う
スペクトログラムを使う人は少ないため、基本機能から外し、別リポジトリの WeVocalAnalyzer（解析のアプリ兼ライブラリ）に移す。Synth からは、ボーカル抽出と同じく追加機能として導入してから使う。移し終わるまでは今の方式を残す。STFT などの計算の部品は wevocal-lib に置いたままにし、F0 など Synth に残る機能は Analyzer に依存させない (2026-10-05)。

### 追加機能の仕組みは PevenMUI に置く
Analyzer でも歌詞の文字化を追加機能にするため、Synth の `src/addons/` を共通にした。導入、保存先、Service Worker の経路、導入のダイアログはどれも音声を扱わないので、wevocal-lib ではなく PevenMUI（`pevenmui/src/addons/`）に置いた。アプリは配信している一覧と IndexedDB を `createAddons` に渡すだけにする。導入のダイアログは、部品の文字を置いた場所の言語で表示する（フックは App の外側で呼ばれ、そこでは言語が分からないため）(2026-10-08)。

### 歌詞の文字化は、Analyzer と Synth の両方で追加機能にする
transformers.js と ONNX Runtime の wasm、読みの辞書で約 43MB あり、使う人は少ない。Analyzer の本体からも外し、同じビルド（`analyzer/vite.addons.lyrics.config.ts`）を両方のアプリで配る。中身が同じなら版も同じになる (2026-10-08)。

### 文字化のモデルも追加機能にし、ファイルは Hugging Face から取る
最初はモデル（Whisper）を transformers.js が自分で取得して保存していたため、追加機能の保存先のフォルダーを使わず、設定から削除もできなかった。モデルを大きさごとの追加機能（`whisper-tiny`、`whisper-base`、`whisper-small`）にした。モデルは tiny でも約 120MB、small は約 560MB あり、配信先（GitHub Pages）の容量に収まらないので、マニフェストだけを配り、各ファイルの `url` に Hugging Face の場所（コミットで固定）を書く。導入の仕組みはそこから取り、大きさと sha256 を確かめて保存先に置く。Worker は transformers.js の `localModelPath` で保存先から読み、transformers.js 自身の保存先は使わない（`analyzer/scripts/whisperAddons.mjs`）(2026-10-09)。

### 読みの辞書（kuromoji）は .dat.bin の名前で配る
`.gz` の名前だと、`Content-Encoding: gzip` を付けて返す配信先がある（Vite の開発サーバーなど）。ブラウザが先に展開するため、導入のときの大きさとハッシュが合わず、kuromoji の展開も失敗した。名前を `.dat.bin` にし、読み込みを差し替えて、圧縮のままでも展開済みでも読めるようにした。kuromoji が使う Node の `path` と zlibjs は、ブラウザ向けのビルドで動かないので、kuromoji から読むときだけ差し替える（`analyzer/vite.kuromoji.ts`。Worker のビルドにも入れる）(2026-10-08)。

## 画面

### アイコンは Font Awesome を使う
`@mui/icons-material` は約3万ファイルあり、この環境ではインストールが時間切れで途中で止まり、一部のアイコンのファイルが欠けて壊れた。使うのは数十個なので Font Awesome に替えた。

### 見た目は角丸を抑え、配色は Google 製品寄りにする
Material 3 の既定（紫・大きな角丸・カプセル型のボタン）は、生成された画面らしい見た目になった。角丸は 4px、配色は青 `#1A73E8` にしている。
同じ理由で、説明文は短くし、背景色付きのボタンは使わない。

### ページ全体をスクロールさせない
パネルを縦に積んでページをスクロールさせていたころは、波形を見ながら「加工」を操作できず、使いにくさの大きな原因になっていた。
画面の高さにぴったり収め（`100dvh`）、スクロールはインスペクタ（スマホはタブのパネル）の中だけにする。Web ページではなく、デスクトップアプリ・モバイルアプリを作っているものとして画面を考える。

### 波形とピッチ帯を画面の主役にする
操作のほとんどは波形とピッチ帯の上で行うため、PC ではツールバーとステータスバー以外の高さをすべて編集領域に使い、設定はすべて右のインスペクタ（幅 320px）に寄せる。
波形の高さは固定値ではなく、置き場所の高さに合わせて伸び縮みさせる（`laneHeights`）。

### PC とスマホは別々に設計する
PC は Windows のアプリのような高さ32px のメニューバー、スマホは Android 風の上部バーと画面下の再生バー。同じ部品を縮めるだけだと、PC では広さを活かせず、スマホでは操作しづらい。

### メニューやダイアログの開閉アニメーションは短くする
既定の長さだと、ツールでは開くまでの待ちが重さとして感じられた。PevenMUI の `theme.ts`（`pevenmui/src/theme.ts`）で 70〜160ms にしている。

### メニューバーの文字は行の高さを固定して中央にそろえる
英字は Roboto、日本語はシステムのフォントで描かれ、フォントごとに上下の余白が違う。そのままだと「WeVocalSynth」と「ファイル」の縦位置がずれた。

### 選択範囲・波形・再生位置は色で描き分ける
波形は青、再生位置の線は文字色、拍の線はオレンジ、選択範囲はシアン（ライト `#0097A7` / ダーク `#4DD0E1`）。同じ青系や文字色にすると重なって見分けられなかった。選択範囲は波形などに隠れないよう最後に描く。

### スマホではページ全体を拡大縮小させない
アプリとして使うので、viewport と `touch-action` で止める。iOS Safari は viewport の指定を無視するため、`gesturestart` も打ち消す。波形のピンチは波形の横方向の拡大縮小に使う。

### 新しい版は、利用者が「更新」を押したときに切り替える
`autoUpdate` だと作業中に勝手に入れ替わる一方、iPad のホーム画面の PWA では開き直しても読み込み直さず、更新されないことがあった。通知して利用者が選ぶ形にし、画面に戻ったとき・1時間ごと・設定の「今すぐ確認」で新しい版を確認する。

通知は `sw.js` の中身が変わると出るので、バージョン番号を上げずにデプロイしても表示される。番号が同じで「新しくないのに通知が来た」ように見えたため、版はコミットの短いハッシュ付き（例: `1.0.3 (47a7e39)`）で表示する。通知には、ビルド時に書いた `version.json`（オフライン用のキャッシュには入れない）から、来た版も表示する (2026-10-01)。

バージョンが同じでコミットだけ違う版（開発版）は、既定では知らせない。開発中はデプロイのたびに通知が来て、利用者には「新しくないのに通知が来た」ように見えるため。設定の「開発者向け」→「開発版の更新を受け取る」を ON にすると知らせる（PevenMUI の `UpdatePrompt` の `devUpdates`。メニューの「更新を確認」も同じ基準。WeVocalExtractor も同じ） (2026-10-03)。

### 文字は選択できないようにし、日本語は文節で折り返す
アプリの操作中にラベルの文字を選択してしまうため、入力欄・ファイル名・リンク以外は選択不可にした（`MuiCssBaseline`）。
ただし設定などの説明文とエラーの文は、調べたり人に伝えたりするときにコピーしたいので、`.selectable` を付けて選択できるようにしている。項目名やボタンの文字は選択できないまま。日本語は `word-break: auto-phrase` で文節ごとに折り返す（Chrome 系のみ有効）。

### Canvas はライト/ダークに応じた色を自分で取り出す
`theme.palette` は常にライトテーマの値だった。そのまま Canvas に使うと、ダークテーマで波形の目盛りの文字が暗いまま見えなくなった。`usePalette()` を使う。

### スライダーの目盛りの色は明示する
MUI の既定では、目盛りがバーの上では背景色、外では文字の補助色で描かれ、どちらも背景と混ざって見えにくかった。PevenMUI の `theme.ts` で色を指定している。

### ブラウザの confirm / alert は使わない
見た目がアプリと合わず、ボタンの文字（OK / キャンセル）も操作の内容を表さない。PWA としてアプリのように使う前提とも合わない。
確認は `useConfirm`（[ConfirmDialog.tsx](../pevenmui/src/dialog/ConfirmDialog.tsx)）で出す。実行ボタンは「削除」「初期化」のように操作の名前にし、取り消せない操作は赤くする。最初のフォーカスはキャンセルに配置する (2026-10-01)。

### ダイアログ・メニューの中では、アプリのショートカットを有効にしない
設定画面で矢印キーや Space を押すと、裏で再生が始まったりピッチが動いたりした。`useShortcuts`（PevenMUI）は `[role="dialog"]` / `[role="menu"]` の中のキーを無視する (2026-10-01)。

### ダイアログは、インストールした Chrome 系ではポップアップで開く
設定・書き出し・音声の作成・ヘルプは、ページ内のダイアログのほか、ポップアップ・別タブ・サブウィンドウ（Window Management API）・PiP（Document Picture-in-Picture）・`<dialog>`・Popover API で出せるようにして比べた。PWA ではポップアップにアドレスバーが表示されず、作業しながら横に置けるのでこれが一番よかった。ふつうのタブではアドレスバーが表示されて見た目が悪く、Chrome 系以外ではポップアップの扱いが違うので、既定の「自動」は PWA かつ Chrome 系だけポップアップ、ほかはダイアログにした。ほかの出し方は「開発者向け」で選べる。別の窓では、元のページの CSS を写し、Emotion のキャッシュ・テーマのクラス・theme-color を窓ごとに持たせる（`pevenmui/src/window/`） (2026-10-02)。

### トラックの欄は、2本以上のときだけ出す
トラックが1本のときは、今までと同じ画面にする（複数トラックを使わない人の邪魔をしない）。欄は広げると波形付きの一覧、折りたたむとタブ。どちらを使うかは、設定ではなく欄の右端のボタンで切り替え、状態を覚えておく (2026-10-01)。

### メニューの構成
右クリックのメニューに機能を足し続けると、項目が多すぎて目的のものを探せなくなる（波形の右クリックは 19 項目になっていた）。次の方針にした (2026-10-04)。

- いちばん上の段は 10 個前後。よく使うもの（試聴、切り取り、コピー、貼り付け）は上の段、まとまりのあるもの（選択、編集、音量、ピッチ、新しいトラックへ、ボーカル抽出）はサブメニューにする
- 状況で中身を変える（ピッチの道具はピッチの帯を右クリックしたときだけ。範囲があれば「選択範囲を書き出す…」）。使用できないものは表示しすぎない
- メニューバーと同じまとまり、同じ名前にする（音量のサブメニューは共通の定義）
- ダイアログを開く項目は名前の後ろに「…」を付ける

問題があれば、この方針ごと見直す。

### スマホの新しい画面
以前のスマホの画面は、なぞると範囲選択、長押しでメニューだったため、選んだあとにできることが画面に表示されず、スクロールは 2 本の指か目盛りの長押しで分かりにくかった。一般的なスマホのアプリ（文字の選択、Ferrite、GarageBand など）にそろえて、新しい画面を作った (2026-10-05)。

- 範囲の選択は、なぞって選択（既定）と、なぞるとスクロールして長押しで選択、から選ぶ。長押しで選択する形を既定にしていたが、使ってみると以前のなぞって選択する方が使いやすかった。範囲を選択したときの編集の列と両端のつまみは分かりやすいので、どちらでも表示する (2026-10-05)
- 範囲を選んだら、波形の下に編集のボタンの列を表示する。範囲の近くに浮かべる形は、指や波形を隠し、位置が動いて押しにくいので採らなかった
- 範囲の両端に指でつかむつまみ（触れる範囲は広く取り、新しい選択より優先する）
- 横向きの右の欄は、たたむ / 固定を選べる
- タブの中では、加工と音量の折りたたみの見出しを表示しない（タブで切り替えているため）

スマホの ⋮ のメニューは、以前は短くするために一部の操作しか入れておらず、マーカーやピッチの表示の切り替えなどがスマホから使用できなかった。PC のメニューバーと同じ中身にし、全部を 1 本に並べると長くなるので、まとまりを選んでから中に入る段階で開く形（PevenMUI の DrillMenu）にした。右クリックのメニューも、指で操作する画面では同じ形にする。トラックには「⋯」を付けて、右クリックのメニューを開けるようにした。

以前の画面も「設定」→「表示」→「スマホの画面」で選べるように残した。指の下を拡大して見せる表示（虫眼鏡）は、使ってみて必要なら追加する。
### 読みの帯は、波形の Canvas の外に置く
一音ずつの範囲は、Waveform の帯の 1 つにはせず、波形の真下に自分の Canvas を持つ部品（`MoraLane`）として置く。Waveform は帯の切り替えと操作が多く、ファイルも大きいため。表示範囲（`view`）は波形と同じものを使い、位置を合わせる (2026-10-09)。

## データ

### 元に戻す履歴は差分だけを持つ
以前は1段ごとに音声まるごとのコピーを持っていて、3分のステレオで20段だと約1.3GB になり、タブのメモリ（ヒープ）が 1.9GB に達した。
今は前後のクリップで変わった部分だけを持つ（先頭・末尾の一致する部分を除く）。段数（既定50）とメモリ（既定512MB）の上限は設定で変えられる。

### プロジェクトファイルに元に戻す履歴は含めない
含めるとファイルが大きくなりすぎる。音声は gzip しても縮みにくく（10秒＋12秒のステレオで約7.6MB）、圧縮に数秒かかって画面が固まったため、.wvsp は無圧縮にした（保存 4.6秒 → 0.05秒）。古い gzip のファイルも読める。

### ファイル選択は拡張子だけで指定し、AIFF は自前で読む
`audio/*` などの MIME 型は OS のダイアログが拡張子の一覧に展開し、並べた拡張子と重なって同じものが何度も発生したので、拡張子だけにした。AIFF は Chrome・Firefox の `decodeAudioData` が読めないので、非圧縮の整数・浮動小数を `wevocal-lib/web/src/aiff.ts` で読む (2026-10-02)。

### 自動保存は IndexedDB に配置する
音声は localStorage の容量（約5MB）に収まらない。設定のような小さいものは localStorage に配置する。

### 自動保存の書き込みは Worker で、ブラウザが空いているときに行う
メインスレッドで保存すると、長い音声で画面が固まった。Worker に渡してから書き込み、原音は変わったときだけ保存する。

### 起動時の復元が終わるまで自動保存しない
復元の前に保存が走ると、まだ何も開いていない状態で前回の作業を上書きしてしまう。

### 多言語化の JSON はビルド時に取り込む
実行時に読み込むと、表示までに待ちが生じる。Vite がバンドルに取り込むので待ちはない。ファイル名は Minecraft と同じ `ja_jp` / `en_us`。

### 編集できるのは、選択中のトラックのみにする
複数のトラックを同時に編集できるようにすると、今までの編集の操作（加工・音量・切り貼り・抽出）をすべて作り直すことになる。選択中のトラックのみを編集し、ほかは一緒に鳴らす参照にすれば、今の操作をそのまま使用できる (2026-10-01)。

### 元に戻す履歴は、全トラックで1本にする
トラックごとに履歴を持つと、元に戻す順番が分かりにくく、メモリの上限も管理しにくい。各段に「どのトラックの差分か」を持たせ、元に戻したらそのトラックに切り替える。トラックの追加・削除の段は一覧を持つが、音声は参照だけなので軽い (2026-10-01)。

### トラックの音量・パンは非破壊、選択範囲の音量・パンは適用で確定する
DTM のフェーダーと同じく、トラック全体の音量・パンは動かした値がそのまま再生と書き出しに入る（音声は書き換えない）。選択範囲だけを変えるときは、ピッチ・長さと同じく「試して、適用で確定」にする。範囲ごとに値を持つと、範囲を後から動かしたときの扱いが難しいため (2026-10-01)。

### フェーダーなどは待たずに保存するが、音声より先にトラックの一覧を書かない
自動保存は音声のために数秒待つので、フェーダーを動かしてすぐ再読み込みすると失われていた。音声以外（フェーダー・ミュート・ソロ・重ねる表示）だけが変わったときは 0.3 秒後に書く。ただし、まだ音声を保存していないトラックがあるときは書かない。音声の無いトラックを一覧に入れると、作業全体を復元できなくなるため (2026-10-01)。

### 画面は「帯」に分け、帯ごとに表示とフォーカスを持つ
波形・スペクトログラム・ピッチ・音量・フォルマントを縦に並ぶ帯にし、それぞれ出す・隠すを選べるようにした（スペクトログラムも波形と入れ替えず、別の帯として並べられる）。ツールバーの操作と切り取り・コピーなどのショートカットは、フォーカスしている帯に反映される。帯ごとの操作が増えても、ツールバーに表示するのは今見ている帯のものだけで済むため (2026-10-01)。

### 音量・フォルマントの帯は、描いてから適用で確定する
フェーダーのような非破壊にはせず、ピッチの曲線と同じく描いた曲線を確かめてから「適用」で音声に書き込む。描いた曲線を範囲の編集と組み合わせたときの扱いが難しくなるため。音量は再生中にすぐ反映できるが、フォルマントは処理が要るので、試聴ボタンで加工して聴く (2026-10-01)。

### フォルマントの帯は、フォルマントだけを動かす
既存の包絡の補正（`formant::correct_varying`）にフレームごとの量を渡すだけにし、ピッチの変更やリサンプルはしない。描いた区間とその前後だけを処理して差し戻すので、描いていない部分の音は変わらない (2026-10-01)。

### 一音ずつの範囲はトラックが持ち、履歴の段にも残す
範囲は音声の位置なので、音声を編集したら動かす必要がある。履歴は音声を差分で持って作り直すため、音声（Clip）に結びつける方法では元に戻せない。範囲をトラック（`Track.morae`）に持たせ、履歴の各段にその前の範囲を残すことで、元に戻すとやり直すで一緒に戻るようにした。編集は `commit` に時刻の写し方（`audio/timeMap.ts`）を渡し、渡さない編集は、長さが同じならそのまま、違えば全体の比で写す。帯の端のドラッグは、マーカーの移動と同じく履歴に積まない (2026-10-09)。
