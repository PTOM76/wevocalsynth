# 決定事項
実装していて問題を踏み、その結果として決まったもの。知らずに触ると同じ問題を踏むので、新しいコードでも同じようにする。

設計全体の方針は [ARCHITECTURE.md](ARCHITECTURE.md)、書き方の決まりは [CODING.md](CODING.md) を参照。

## 音声処理

### 伸長の最後のフレームは、入力の最後のフレームに合わせる
最初は出力位置を伸縮率で割って入力位置を決めていた。これだと末尾でフレームが入力の終端をはみ出して無音を重ね合わせ、伸ばした音の最後だけギザギザになった。
はみ出さないよう位置を止めると、今度は最後の断片を何度も繰り返してうなりになった。

そのため `TimeMap::frame_pos` で「最後の出力フレーム＝最後の入力フレーム」になるよう対応づけている。WSOLA と Phase Vocoder の両方がこれを通る。テストは `stretch_tail_is_steady`。

### WSOLA の類似度はフレームの重なる部分だけで計算する
フレーム全体で比べると、末尾では比較する範囲が入力の外にはみ出す。重なる前半だけで比べれば常に入力の内側に収まり、計算量も半分になる。

### ピッチ変更は「伸縮してからリサンプル」で行う
長さはピッチ比に影響されず、ピッチ変更と時間伸縮を1回で指定できる。処理の順番で結果が変わる心配もない。
ピッチマークを使う方式（PSOLA）は F0 推定が前提で重いため、今は使っていない。

### フォルマント補正はリサンプルの前に行う
リサンプルの後だとピッチが上がって倍音の間隔が広がり、包絡をうまく推定できない。前なら元の声の高さのまま推定できる。

### ボーカル／楽器の自動判定は目安として扱う
「鳴っているフレームのうちピッチが取れた割合」で判定している。正弦波の和音は1つの長い周期を持つため、「ボーカル」と誤判定される（合成音で確認）。
初期値を決めるだけにし、画面の切り替えを優先する。実際の素材での精度はまだ確かめていない (2026-09-27 時点)。

### リアルタイムのループ試聴は、適用とは別の簡易な方式を使う
WSOLA / Phase Vocoder は音声をまとめて処理する前提で、再生しながら少しずつ処理する形にするのは重い。
ループ試聴は AudioWorklet のグラニュラー方式にし、「適用」と通常の「試聴」は高品質な処理のままにした。音がザラつくのはこの割り切りのため。

## 実行と読み込み

### スペクトログラムと F0 は、表示を ON にしたときだけ計算する
ファイルを開いたときに表示の ON/OFF とパラメータを前のファイルから引き継いでいた。そのため開いた直後にスペクトログラム・F0・プレビューの処理が Worker に積まれ、読み込みが遅く感じられた。
今はファイルを開くと表示を OFF、パラメータを初期値に戻す。処理方式とフォルマント保持の ON/OFF だけは、好みの設定として残す。

### 重い処理はすべて1つの Worker に順番に送る
並列にすると WASM のメモリを複数持つことになり、長い音声では足りなくなる。順番に処理される前提なので、解析の結果は「どのクリップのものか」を確かめてから使う（古い結果を捨てる）。

### プレビューは、同じ設定のときだけ使い回す
「適用」で加工済みプレビューを差し込むときは、クリップ・範囲・パラメータがすべて同じかを確かめる。1つでも違うものを差し込むと、画面の設定と違う音になる。

## 画面

### アイコンは Font Awesome を使う
`@mui/icons-material` は約3万ファイルあり、この環境ではインストールが時間切れで途中で止まり、一部のアイコンのファイルが欠けて壊れた。使うのは数十個なので Font Awesome に替えた。

### 見た目は角丸を抑え、配色は Google 製品寄りにする
Material 3 の既定（紫・大きな角丸・カプセル型のボタン）は、生成された画面らしい見た目になった。角丸は 4px、配色は青 `#1A73E8` にしている。
同じ理由で、説明文は短くし、背景色付きのボタンは使わない。

### PC とスマホは別々に設計する
PC は Windows のアプリのような高さ32px のメニューバー、スマホは Android 風の上部バーと画面下の再生バー。同じ部品を縮めるだけだと、PC では広さを活かせず、スマホでは操作しづらい。

### メニューやダイアログの開閉アニメーションは短くする
既定の長さだと、ツールでは開くまでの待ちが重さとして感じられた。`theme.ts` で 70〜160ms にしている。

### メニューバーの文字は行の高さを固定して中央にそろえる
英字は Roboto、日本語はシステムのフォントで描かれ、フォントごとに上下の余白が違う。そのままだと「WeVocalSynth」と「ファイル」の縦位置がずれた。

### Canvas はライト/ダークに応じた色を自分で取り出す
`theme.palette` は常にライトテーマの値だった。そのまま Canvas に使うと、ダークテーマで波形の目盛りの文字が暗いまま見えなくなった。`usePalette()` を使う。

### スライダーの目盛りの色は明示する
MUI の既定では、目盛りがバーの上では背景色、外では文字の補助色で描かれ、どちらも背景と混ざって見えにくかった。`theme.ts` で色を指定している。

## データ

### プロジェクトファイルに元に戻す履歴は含めない
履歴は音声そのものを最大20段持つので、含めるとファイルが大きくなりすぎる。音声は gzip しても縮みにくい（10秒＋12秒のステレオで約7.6MB）。

### 自動保存は IndexedDB に置く
音声は localStorage の容量（約5MB）に収まらない。設定のような小さいものは localStorage に置く。

### 起動時の復元が終わるまで自動保存しない
復元の前に保存が走ると、まだ何も開いていない状態で前回の作業を上書きしてしまう。

### 多言語化の JSON はビルド時に取り込む
実行時に読み込むと、表示までに待ちが出る。Vite がバンドルに取り込むので待ちはない。ファイル名は Minecraft と同じ `ja_jp` / `en_us`。
