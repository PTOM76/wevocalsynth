# 機能の仕組み
読み込みから書き出しまでのデータの流れと、トラック・再生・保存がどう動いているかをまとめる。(2026-10-03 時点)

関連: [アーキテクチャ](ARCHITECTURE.md) / [ファイル構成](STRUCTURE.md) / [アルゴリズム](ALGORITHM.md) / [決定事項](DECISIONS.md)

## データの流れ

### 読み込みから出力まで

| 段階 | 処理 |
| --- | --- |
| 読み込み | `decodeFile` で `Clip`（サンプルレート＋チャンネルごとの `Float32Array`）にする。WAV・MP4/M4A はファイルからサンプルレートを読み、同じレートでデコードする。AIFF / AIFF-C はブラウザが読めないので `aiff.ts` で読む（非圧縮の整数 PCM と浮動小数）。読み込み中は `useTask` で進捗を出す（デコード中は進み具合が取れないので -1） |
| 初期化 | `useHistory.reset` で履歴を作り直し、ボーカル／楽器を自動判定してパラメータの初期値にする。テンポも解析して BPM・1拍目をプロジェクトに入れる |
| 編集 | 編集のたびに新しい `Clip` を作って、操作名と一緒に `commit` する（元のクリップは書き換えない） |
| 出力 | 書き出しダイアログで `exportAudio` を呼び、WAV / MP3 / Opus にしてダウンロードする（`hooks/useOutput.ts`）。選んでいるトラック（フェーダーを掛けたもの）か、全トラックのミックス（`mixClips`。ミュート・ソロとフェーダーに従う）を選べる |

### 加工（ピッチ・長さ）
1. `applyEditToRanges` が各範囲を後ろから順に処理する（前の範囲の位置がずれないように）
2. 範囲ごとに `processRange` が Worker へ送り、wasm の `process_planar` で処理する
3. `spliceProcessed` で元の位置に差し戻す。継ぎ目は 5ms のクロスフェードでつなぐ

`applyPitchCurve`（ピッチカーブ）は曲線のある部分だけを切り出して処理し、同じように差し戻す。

ピッチの線を掴んで動かす（`components/waveform/usePitchGrab.ts`）は、押した所から線が 10px 以内なら掴み、選択範囲の中ならその範囲、外なら無声で途切れるまでを、掴んだときの曲線から平行に動かして `usePitchTarget.replace` に渡す。

ピッチの一括操作（半音上下・平らにする・音階に揃える・ビブラート・MIDI の当てはめ）は、どれも「目標ピッチの曲線を返す関数」（`audio/pitchTools.ts`）で、`usePitchTools.edit` に渡す。MIDI は `audio/midi.ts` で読み、その時刻に鳴っている音符（和音なら一番高い音）を目標にする（`fitMidi`）。

同じ設定の加工済みプレビューがあれば、2 を飛ばしてプレビューをそのまま差し込む。全体を加工したときは、差し戻さずに加工後の音声をそのまま使う（全体の長さの配列をもう1つ作らない）。

### 描いた曲線（音量・フォルマント）
- 曲線は 10ms 間隔の配列で、どの `Clip` に描いたかと一緒に持つ（`hooks/useLaneCurve.ts`）。編集で `Clip` が変わったら使わない
- 音量: 再生中は `usePlayer` が曲線を Web Audio の予約（`setValueCurveAtTime`）で鳴らす。「適用」で `applyGainCurve` が音声に掛ける
- フォルマント: 再生にすぐ反映できないので、試聴のときに描いた区間だけを加工する（`hooks/useFormantCurve.ts`）。「適用」で `applyFormantCurve` が Worker の `formant_curve_planar` を呼ぶ

## トラック
編集できるのは**選択中のトラックのみ**で、ほかのトラックは一緒に鳴らして聴く参照になる。今までの編集の操作（加工・音量・切り貼り・抽出）は、そのまま選んでいるトラックのクリップに効く。

| 持つもの | 場所 | 元に戻す | 保存 |
| --- | --- | --- | --- |
| トラックの一覧（名前・原音・加工後） | `useHistory` | できる | する |
| フェーダー（音量 dB・パン） | `useTracks` | できない | する |
| ミュート・ソロ・重ねる表示 | `useTracks` | できない | する |

- フェーダー・鳴らし方・重ねる表示は `TrackSettings`（`audio/tracks.ts`）にまとめる。保存するときの形（`StoredTrackSettings`。古いファイルと同じく volume・pan・invert・mute・solo・overlay を平らに並べる）との変換は `toStoredSettings`・`fromStoredSettings`・`pickStoredSettings` だけで行い、プロジェクトファイル・自動保存・開き直したときの復元はどれもこれを通す。項目を足すときは `tracks.ts` だけを直す
- 履歴は1本で、各段は「トラック id と差分」か「トラックの一覧」。元に戻すと、変わったトラックに切り替わる（`audio/tracks.ts`、`hooks/useHistory.ts`）
- トラックを増やす操作: 複製、ファイルの追加、ボーカルと伴奏に分ける（`separateBoth`、推論は1回）、統合（`mixClips`、一番上のトラックのサンプルレートに合わせる）、音声の作成（`audio/synth.ts`）
- トラックの欄（`components/tracks/TrackPanel`）: 2本以上のときだけ出す。広げると波形付きの一覧（小さな波形は大きな波形と同じ表示範囲）、折りたたむとタブ
- 並び替えはドラッグで行い、元に戻せる（`useTracks.move`、`components/tracks/useTrackDrag.ts`）
- 複数選択（Ctrl / Shift）は、右クリックメニューでまとめて操作する対象を決めるためだけのもので、画面の状態として持つ（`useTrackArea`）。編集するのは選んでいる1本のまま
- ほかのトラックの波形は、右クリックメニューで大きな波形の後ろに薄く重ねられる（`drawGhostWave`）

## 再生

| 種類 | 実装 | 用途 |
| --- | --- | --- |
| 通常の再生 | `usePlayer`（AudioBufferSourceNode） | 全体・範囲の再生。ループ再生（ツールバー）もこれ |
| 試聴 | `usePreview` の結果を `usePlayer` で再生 | 高品質な加工結果の確認 |
| ループ（加工の欄） | `useRealtimePreview`（AudioWorklet のグラニュラー方式） | スライダー操作中の即時確認 |
| 曲線の試聴 | `usePitchTools` / `useFormantCurve` が曲線の部分だけ加工し、`usePlayer` で再生 | ピッチ・フォルマントの曲線を適用する前の確認 |

### 音の通り道（`usePlayer`）
```
選んでいるトラック: 音源 → 適用前の音量 → 適用前のパン → 音量の曲線 → フェーダー（音量・パン） → ミュート → メーター ┐
ほかのトラック:     音源 ───────────────────────────────────────→ フェーダー（音量・パン） → ミュート → メーター ┼→ 全体（左右のメーター）→ 出力
```
- 適用前の音量・パンは、選択範囲の境目の時刻に予約する（5ms で切り替え）。再生中に動かしても入れ直す
- ミュート・ソロで鳴らさないトラックも再生しておき、ミュートの音量を 0 にする（再生中の切り替えをすぐ反映するため）
- パンは StereoPannerNode（モノラルも左右同じ音のステレオにしてから）。適用（`panRange`）と書き出し（`applyFader`）も同じ式なので、聴こえる音と結果が一致する
- 止めたら、再生のたびに作った部品をすべて切り離し、AudioContext を一時停止する
- 音量メーター（`LevelMeter`）は AnalyserNode を毎フレーム Canvas に直接描く。鳴っていなくて表示も消えたら 0.25 秒おきの確認にする

再生中の位置は React の状態として更新しない（更新すると画面全体が毎回描き直されて重くなった）。再生位置の線・時間の表示・自動スクロールは、それぞれ `livePosition()` を自分で読む。

- ループ再生（`usePlayer` の `loop`）: 範囲の終わりの `onended` で、範囲の先頭から音源ごと作り直して鳴らす（適用前の音量・曲線の予約も作り直すため）。つなぎ目に数十 ms の隙間が出ることがある
- 再生中に `clip` が変わったら（トラックの切り替え・原音と加工後の切り替え・元に戻す）、止めずに同じ位置から新しい `clip` で鳴らし直す。新しい `clip` の終わりを過ぎていれば止める
- 加工の欄のループは別の AudioContext（素材と同じサンプルレート）で、選んでいるトラックの範囲だけを鳴らす。上の通り道を通らないので、ほかのトラック・フェーダー・メーターは効かない。再生位置の線は、worklet が約 1/30 秒ごとに送る読み位置から求める（戻るのは折り返しのときだけにして、線のぶれを抑える）。範囲の中を押すと `seek` メッセージで読み位置を移す

## 保存

| 対象 | 保存先 | 形式 |
| --- | --- | --- |
| プロジェクト | 保存先を選ぶ画面（Chrome、Edge）かダウンロード（.wvsp） | 無圧縮（"WVSP"＋ヘッダ JSON＋トラックごとの f32 の原音・加工後）。版 2 はヘッダにトラックの一覧（名前・フェーダー・ミュート・ソロ・重ねる表示）とテンポ（BPM・拍子・1拍目。古いファイルには無い）を持つ。版 1（1トラック）と古い gzip のファイルも読める |
| 自動保存 | IndexedDB（`wevocalsynth` / `kv` / `autosave:track:<id>:original`・`…:edited`・`autosave:meta`） | `Float32Array` をそのまま。音声は変わったトラックだけ書く。以前の形式（1トラック）も読める |
| 設定 | localStorage（`wevocalsynth.settings`、画面の状態は `wevocalsynth.*`） | JSON |

自動保存の動き（`hooks/useAutosave.ts`、`project/autosave.ts`）:

- 音声は 4MB ずつに分けて、ブラウザが空いている間に少しずつ Worker に渡す（所有権ごと渡すので複製しない）。Worker が組み立ててから書く。まとめて複製すると、数百MB の複製で画面が止まった
- 加工していないトラック（加工後が原音と同じ）は、加工後の音声の代わりに印だけを書く
- フェーダーなど音声以外だけが変わったときは、音声がすべて保存済みなら 0.3 秒後にすぐ書く
- 起動時の復元も Worker で読み、音声は所有権ごと受け取る

「設定」→「データ」から、作業データ・オフライン用キャッシュ・設定を削除できる（`project/storage.ts`）。

原音の退避（メモリの節約。`audio/originalStore.ts`）:

- 加工したトラックの原音（`Track.original`）を IndexedDB の `original:<uuid>` に置き、Clip の `channels` だけを空にする。Clip のオブジェクトは残すので、トラック、履歴、自動保存からの参照は変わらない
- 使う前に `restoreClip` で戻す: 原音の再生（戻るまでは加工後を出す）、テンポでの伸縮、プロジェクトの保存、自動保存（戻して保存し、退避し直す）、メモリが足りないときの抽出の作業の保存
- 退避する時: 設定の「メモリを節約する」が有効なら加工のたびに（既定はスマホとタブレットだけ）、ボーカル抽出の前は設定によらず
- 退避中の Clip は画面や再生に渡さない（波形や解析は Clip ごとに覚えるので、空のまま残る）。起動時に前回の残りを消す
- 履歴は加工のたびに差分（変わった部分）だけを持つので、原音ほどは大きくならない

開く場所と保存先（`project/fileAccess.ts`）:

- Chrome、Edge では File System Access API の選択画面で開く、保存する。用途（開く、プロジェクト、音声）ごとに `id` を渡し、フォルダをブラウザに覚えさせる。使えないブラウザは input とダウンロード
- 保存先の画面はユーザー操作の中でしか出せないので、書き出しのエンコードの前に選ぶ。ダイアログを別ウィンドウで開いているときは、そのウィンドウから出す
- 最近使用したファイルは、ファイルの参照（ハンドル）を IndexedDB の `recentFiles` に最大 8 件持つ。開いた、ドロップした、保存したプロジェクトのファイルを記録する（書き出した音声は記録しない）
- インストールした PWA は .wvsp を開くアプリとして OS に登録する（`vite.config.ts` の `file_handlers`）。ダブルクリックで起動したファイルは `launchQueue` で受け取り、起動時の復元をしない
- 自動保存が OFF で PWA として開いているときは、未保存の変更があれば閉じる前に確認する（`hooks/useLeaveGuard.ts`。操作履歴が保存時から変わったかで判断する）
